# HRS Staff (フロント係アプリ)

フロント係アクターの画面だけを持つSPAです。ワークスペース全体の構成と開発手順は
ワークスペース直下の [`README.md`](../../README.md) を参照してください。

## 画面（UCとの対応）

| 画面 | パス | ユースケース | 09のバウンダリ |
|---|---|---|---|
| 予約番号検索 | `/` | UC2・UC3への入口 | — |
| 予約処理 | `/reservations/:slug` | UC2 チェックイン / UC3 チェックアウト | CheckInUI / CheckOutUI |

チェックアウトは2段階です。「宿泊料金を計算する」で未払いの請求を発行し、
利用者へ金額を案内して支払いを受領してから「支払い受領を登録」します。請求を
発行しただけでは予約はCHECKED_INのままで、客室も使用中のまま維持されます。

## 利用者アプリと別オリジンにする理由

ブラウザの隔離単位はオリジン（スキーム・ホスト・ポート）であってパスではありません。
同一オリジンでパスだけ分けた場合、cookie・localStorage・CSPはすべて共有され、
利用者側のXSS1つでこの画面が丸ごと取られます。開発時にポートを分けているのは
本番でホストを分ける前提を保つためで、`vite.config.ts` の `server.port` が
利用者アプリの5173に対して5174になっています。

## セキュリティ上の位置づけ（重要）

**このアプリには認証がありません。** オリジン分離は「認証を掛ける場所を作る」ための
前提であって、それ自体はアクセス制御ではありません。デモ以外で公開する場合は、
少なくとも次の両方が必要です。

1. このアプリの配信オリジンをVPNやリバースプロキシのBasic認証の背後に置く
2. バックエンドAPIにフロント係の認可を入れる。`POST /reservations/{id}/check-in`、
   `/charge`、`/payment` は現在誰でも呼べるため、1だけでは塞がらない

## 開発

```bash
pnpm --filter @hrs/staff dev     # http://localhost:5174
```

APIのベースURLは `VITE_API_BASE_URL`（既定 `http://localhost:8080`）で変更できます。
